## Versión del workspace y dependencias

Upstream sigue con `version.workspace = true`, así que los `Cargo.toml` importados no pueden copiarse
tal cual: se mantiene la versión literal (`0.128.0` → **`0.129.0`**). Además, en este rango el motor
gana una dependencia opcional que sí hay que declarar:

| Cambio en `crates/phase-engine/Cargo.toml` | Motivo |
| --- | --- |
| `crc32fast = { version = "1", optional = true }` | El caché de fixture lo usa para su checksum |
| `test-support = [ …, "serde_json/raw_value", "dep:crc32fast"]` | Activa el caché y el modo `raw_value` |

`crc32fast` ya estaba en `Cargo.lock` (lo arrastra `flate2`), así que el lock sólo cambia las tres
líneas de versión de los crates importados **y** añade `crc32fast` a la lista de dependencias de
`phase-engine`. Ninguna dependencia externa nueva, ninguna versión que resolver.

Se mantiene la desviación declarada del pin anterior: `[[bin]] coverage-report` lleva `test = false`
en local (upstream lo dejó de comentar en este rango y ahora lo ejecuta), porque su prueba inline
depende de datos que Mesa no importa. Es la única línea del `Cargo.toml` que no es idéntica al
tarball, aparte de `version`.

## Cómo se comprobó la procedencia

`bun run engine:verify` recorre `crates/phase-engine/src`, ordena las rutas y hashea
`ruta \0 sha256(fichero)`; el esperado vive sólo en `docs/PHASE-UPSTREAM-PIN.json`. El digest del
tarball crudo coincide con el local (`0395ef01…`) porque el rango **no** cambia `types/format.rs`: la
adaptación de `client-mirror` ya está dentro del árbol y el hash se calcula sobre el árbol local. Si
esa huella cambia en el futuro sin un pin nuevo, `engine:verify` falla.
