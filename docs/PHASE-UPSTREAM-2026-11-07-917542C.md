## Los datos que el código embebe

`phase-ast` no solo trae `src`: hay ficheros de `crates/phase-ast/data/` que el
código incluye en tiempo de compilación, y uno de ellos es **nuevo** en este
rango. `types/confirmed_misparse.rs` (del commit `6d99397f`) hace
`include_str!("../../data/confirmed-misparses.toml")` — 540 900 bytes con las
caras que el censo de cobertura confirma mal interpretadas. Sin ese fichero la
crate no compila, que es exactamente lo que dijeron las anotaciones de los
trabajos de WASM y paridad nativa en el primer intento:

```
error: couldn't read `crates/phase-ast/src/types/../../data/confirmed-misparses.toml`
       : No such file or directory (os error 2)
  --> crates/phase-ast/src/types/confirmed_misparse.rs:99
```

También se sincronizan desde el pin nuevo los catálogos que ya existían y
cambiaron: `known-tokens.toml` (`f6858289` y `c53dd8a8`), su overlay y el sello
`mtgjson-vintage` (2026-11-01 → 2026-11-10). `oracle-subtypes.json`, `build.rs`
y `cr-audit-report.md` son idénticos al pin anterior y no cambian.

## Las pruebas upstream importadas

Además de `src`, el árbol importa las pruebas de integración del motor
(`crates/phase-engine/tests/`), que es lo que ejecuta el flujo
`phase-source-regressions.yml` sobre el código real de Phase. **Estaban dos pines
atrás**: 56 ficheros de prueba seguían en una versión anterior y uno de ellos ya
no compilaba contra el motor nuevo, que es lo que tumbó el trabajo «Ripple
visibility and attacked-recipient Rust tests» en el primer intento.

En esta importación se han sincronizado **todos los ficheros de prueba y de
fixtures que Mesa conserva** (2 219 ficheros de `tests/integration`, sus
subdirectorios `fixtures`, `rules` y `snapshots`, y `tests/fixtures`): 121
ficheros cambian. `diff -rq` contra el tarball nuevo ya no encuentra diferencias
en los ficheros conservados.

La poda deliberada se mantiene: **69 ficheros de prueba upstream no se importan**
(53 que ya se dejaban fuera antes —Horde, escenarios que necesitan datos que no
entran en el árbol— y 16 nuevos de este rango). No se añaden aquí porque ninguno
hace falta para las regresiones que Mesa ejecuta y varios dependen de piezas no
importadas.

Los `tests/` y los `data/` **no** forman parte del digest de `engine:verify`, que
cubre solo `crates/phase-engine/src`.

- `diff -rq` de `crates/phase-engine/tests` contra el tarball nuevo: sin diferencias en los ficheros conservados (quedan 69 ficheros upstream sin importar, por poda).

- Este sandbox **no tiene toolchain de Rust** (`cargo`, `rustc` y `wasm-pack` no están instalados, y `static.rust-lang.org` no es alcanzable desde aquí), así que la compilación la validan los trabajos **Native parity** y **WASM build** de CI sobre este mismo commit. La verificación local se limita a `engine:verify`, `check`, pruebas de `src/lib` y el build estático, que no compilan Rust.
